# Dark / AI Product Launch

A software launch treatment built around a dark stage, selective interface highlights, short text bridges, and a visible action-to-result story. Useful for AI tools, coding products, creative software, and feature launches with genuine interface assets.

This is a selectable style inside the product skill. Its sustained dark interface treatment and creation/refinement story distinguish it from the general focused SaaS demo and the material-focused cinematic reveal. See the [reference study](references/2026-11-14-gemini-canvas.md) for the actual visual evidence and its limits.

## Visual system: original production recipe

The following colors, dimensions, and timing suggestions are design starting points for new videos, not measurements from the reference.

- Use a near-black stage, e.g. `#06080E`, readable off-white text `#F4F7FF`, and one or two brand-compatible accents, e.g. blue `#638BFF` and violet `#A58AFF`.
- Reserve glow for an active control, panel edge, or important word. Keep body text sharp and unglowed. Reduce background bloom when it weakens the product silhouette or text contrast.
- Use one primary interface panel at a time. Supporting panels can establish depth briefly, then yield to the readable action. Keep one consistent perspective and lighting direction.
- Alternate concise text scenes and actual product scenes. Accent one useful term rather than coloring the entire sentence. Use an available licensed sans; do not require Google fonts, icons, branding, or proprietary assets from the reference.
- Build the layout natively at 1080 × 1920. Place short text above/below a focused interface crop. Avoid shrinking a whole desktop editor to fit the vertical canvas.

## Motion direction

Use these as proposed animation choices, then check them in a real preview after the user selects this style. The reference was studied through static samples; exact trajectories, easing, cut durations, and audio sync were not measured.

- Enter a panel with a restrained perspective settle; reduce tilt before reading begins. Suggested starting duration: 16–24 frames at 30 fps.
- Let the active UI region brighten while surrounding elements recede. A suggested focus change is 8–14 frames followed by an appropriate reading hold.
- Use a cursor/touch cue only for a supported action. Show the selected area, actual control, and resulting state in an understandable order. A luminous border cannot substitute for a demonstrated result.
- Use text bridges to connect feature beats. Keep each bridge short and align it to recorded narration; design the timing from the new voice track rather than assuming the reference's beats.
- Limit perspective travel and decorative motion while code or dense UI is visible. Show a small, relevant excerpt and hold the result long enough to recognize.

## Adaptable 30-second product story

| Time | Purpose | Suggested treatment |
| --- | --- | --- |
| 0–3s | Hook | One supported outcome with a clear product identifier |
| 3–8s | Context/input | Actual prompt, source item, or starting UI state |
| 8–18s | Refine | One or two verified actions with a readable focus change |
| 18–25s | Result | The real resulting artifact, preview, or completed task |
| 25–30s | CTA | Stable product view, one action, clean finish |

This is a new production plan, not a reproduction of the reference's 60-second sequence. Adapt it to the user's requested length and actual product capability.

## Inputs and product truth

Prefer real UI captures and recordings with before/action/after states. If only screenshots exist, create a labeled illustrative feature walkthrough rather than implying a live interaction was recorded.

Keep actual UI colors and text. If the product has no dark theme, use a dark surrounding stage while retaining its genuine light UI; do not invent native dark-mode support. Use supplied code, documents, or generated artifacts that actually demonstrate the claimed feature. Do not transfer another product's AI functionality, results, speed claims, brand mark, or sample user information.

A physical product can use this treatment when a genuine screen, app, or digital workflow is central. For a purely material/object reveal, the cinematic style may be a more useful recommendation; the user still makes the selection.

## Natural female voice and sound

Use composed, articulate female delivery with short pauses before the action and result. Start around 130–150 words/minute and shorten the script when needed. Keep music and effects below narration. The main skill's real-recording/AI-voice distinction still applies; no reference voice was heard or copied.

## Preview and quality checks

After explicit user style selection, make a 6–8 second 540 × 960 preview showing one text bridge, one clear interface action/state change, and its understandable result. Include the actual female voice sample when available and label missing audio honestly.

Check phone-size UI readability, accurate product state, glow boundaries, perspective distortion, stable highlights, caption clearance, and whether the result remains visible long enough. Use the parent skill's render and audio checks for final 1080 × 1920 output. No preview has been validated merely by adding this guide.

Stage one genuine phone UI on a dark brand-compatible field, using restrained lines/highlights for continuity. A short set of supporting views can establish breadth, then return to one readable screen. Stop large perspective changes while text matters.
