# SaaS / Product Demo

Make a digital product's benefit clear through an understandable interface action and its result. For a physical product, use this style only when a genuine companion app or digital workflow is relevant.

## Visual system

- Use a neutral surface `#F5F7FA`, ink `#111827`, and the actual brand accent. The real interface colors and spacing take precedence over a generic theme.
- Use a clean sans with clear numerals and UI labels. Crop a desktop screen into focused vertical details instead of shrinking the entire desktop to fit a phone.
- Keep the active control, action, and result in the same visual path. Use a restrained device frame only if it helps orientation.
- Use callout chips, focus masks, and connecting lines sparingly. Maintain enough surrounding UI context to understand the action.

## Motion grammar at 30 fps

- Interface entry: 12–20 frames, subtle rise and scale settle.
- Focus movement: 10–18 frames with 1–2 second holds on the relevant control and result.
- Pointer or touch cue: move intentionally, pause, then activate. Do not animate clicks on unsupported or imaginary functionality.
- Use consistent zoom anchors. Zooming into a screenshot cannot reveal more detail than the source contains.
- Prefer match cuts between truthful before/action/after states; do not hide an unexplained feature jump behind flashy effects.

## Product story: adaptable 30-second example

| Time | Purpose | Treatment |
| --- | --- | --- |
| 0–3s | Problem | One familiar task and its friction |
| 3–7s | Product context | App name and relevant screen |
| 7–20s | Workflow | Two or three verified actions with clear results |
| 20–26s | Benefit | Supported outcome, without invented time savings |
| 26–30s | CTA | One next step, e.g. try the demonstrated feature |

## Inputs and female voice

Prefer real screenshots or screen recordings. If only marketing screenshots exist, make a feature walkthrough rather than inventing a working demo. Label reconstructed UI or sample data as illustrative. Use no fabricated testimonials, dashboards, customer data, or performance claims.

Voice: helpful, assured female delivery, roughly 130–150 words/minute. Narrate the user's action and benefit, leaving time to inspect the interface. Speak product names and acronyms consistently.

## Preview and quality checks

Show one complete action/result pair with narration. Check UI text at phone size, ensure pointer timing matches the result, and verify the demonstrated function against provided evidence. Blur private information in supplied recordings when needed.

## Reference improvements

### Optional visual variations

Choose one treatment that explains the actual product; retain the focused demo baseline when none helps. These visual recipes were studied through storyboards, not continuous playback. Their animation timing must be designed and checked in a real preview.

- **Workflow cards:** group genuine input types into distinct cards, then show an actual processing/result state. A pastel background can organize the group. The [short UI reference](references/2026-11-14-workflow-cards.md) has limited-resolution visual evidence; do not infer its interaction details.
- **Data intelligence:** connect product context, events/notifications, and filtered results with a consistent dot/line vocabulary. Use only verified figures and clearly illustrative particles. See the [VAINU study](references/2026-11-14-data-intelligence.md).
- **Depth UI:** use isolated interface panels, occasional light/dark scene contrast, and one small visual connector between steps. Add a success state only for an actual completed action. See the [Virgil study](references/2026-11-14-depth-ui.md).
- **Device and theme showcase:** feature one readable phone, alternate real light/dark screens, and briefly use surrounding cards to establish breadth. Reflow a wide device wall into a vertical composition. See the [banking-app study](references/2026-11-14-device-theme-showcase.md).
- **Light UI:** keep a genuine query/input and resulting document state readable on a restrained white surface. Design the action from actual product evidence; do not infer a complex interaction or tool-icon animation from a promotional poster. See the [light-interface study](references/2026-11-14-light-ui.md).
- **Phone fan and benefit label:** briefly show several phone views, then isolate one clear screen beside one short supported benefit. Adapt colors and labels to the actual app. See the [template-promo study](references/2026-11-14-phone-fan-promo.md); it is a design reference, not an instruction to buy or use its editor.
- **Phone pose:** use controlled device perspective to introduce the app, then settle for reading. A background-ring motif is optional and must stay subordinate to the screen. See the [phone-pose study](references/2026-11-14-phone-pose.md); exact camera and object paths were not reviewed.
