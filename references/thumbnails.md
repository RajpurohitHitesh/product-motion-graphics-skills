# Product covers and thumbnails

Use when composing a Short's opening or producing a requested thumbnail. Match the selected video's visual language and supported claim. The faceless package contributes cover-frame selection and a code-generated style-sheet workflow; it does not provide a measured click-through recipe. The AmezPrice poster and the three supplied players contribute visible composition examples; see [the comparison](video-studies/2026-11-14-craft-upgrade.md).

## Compose for a small preview

Use one recognizable product/UI hero, one short viewer-facing promise (usually 3–6 words), and at most one supporting callout. Give the headline a distinct contrast area and the hero a clean silhouette. A logo is a small identifier; it should not consume the headline area. Use a real UI detail, not an unreadable full dashboard, to support the promise.

Reuse [the video's heading system](heading-system.md) for font pairing, keyword marking, contrast and meaningful line breaks. A cover title can be larger than a step heading, but it should belong to the same visual family. Keep the supporting callout smaller and readable rather than making every text element compete as a headline.

For a 1080 × 1920 cover, begin with the shared safe-area guidance and check both the full portrait view and a centered square crop. Keep the core headline and recognizable product inside both where practical. This is a composition check, not a guarantee about every platform's current crop. Inspect at approximately 270px wide without zooming in.

Choose a stable frame after the key elements settle. Avoid mid-transition blur, partly typed text, half-visible cards, and ambiguous disabled/enabled states. The first frame can already be a deliberate composition without adding a long static intro. A dedicated thumbnail can reuse the same scene components and assets while moving the headline into a clearer cover layout.

## Recipes by existing style

| Style | Cover recipe |
| --- | --- |
| 1 Feature Explainer | One actual feature crop, short benefit headline, one anchored detail/metric callout |
| 2 How-To | Visible outcome/control, direct task title, small step-count badge only for the real sequence |
| 3 SaaS Demo | Readable result panel, product identifier, single task/outcome promise |
| 4 Layered App | One dominant screen and one supporting lifted crop; foreground remains readable |
| 5 Minimal | Large product silhouette, generous space, one quiet short headline |
| 6 Kinetic | Strong headline with one marked word plus a distinct product anchor |
| 7 Infographic | One verified number/relationship, units visible, product/context still recognizable |
| 8 Bold Social | Large product and high-contrast hook; one genuine offer badge when supplied |
| 9 Cinematic | Clear lit silhouette/material detail and restrained bright type on the dark stage |
| 10 Dark AI | One real result/interface crop with controlled edge light and a short supported promise |

For AmezPrice, examples of topic copy include “Check price history”, “Set your price alert”, and “Amazon → AmezPrice”. Adapt language to the brief. Do not add invented savings, an unsupported score interpretation, or a live-price guarantee. Use current screenshots for actual metric callouts.

## Export and handoff

When requested, export one cover at the final portrait resolution as PNG/JPEG and note the candidate frame/time. Generate multiple concepts only when requested or materially useful for an unresolved choice. Reuse existing rendered frames where sufficient; a cover does not need a second full-video render.

If titles/descriptions are requested, provide a concrete task/benefit title and a concise accurate description; include hashtags only when wanted. A local cover file is not evidence that a platform accepts a custom thumbnail through a particular upload workflow. Publishing and upload configuration remain separate requested work.
